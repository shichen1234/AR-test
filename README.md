# 药盒 WebAR 图片追踪 Demo

这个版本先不使用 3D 模型，而是用 OpenCV.js 的 ORB + RANSAC 单应性（Homography）做自然特征追踪：

- `target.jpg`：从你上传的药盒照片中裁出的顶部区域，作为识别目标。
- `ar-content.jpg`：之前上传的彩色烟雾图片，作为 AR 显示内容。
- `index.html`：手机浏览器打开后调用后置摄像头，识别药盒顶部并把图片透视变换到目标表面。

## 手机测试

必须使用 HTTPS（例如 GitHub Pages），不能直接用 `file://` 打开。

上传这三个文件到 GitHub 仓库根目录，然后开启 GitHub Pages。

打开页面后：
1. 允许摄像头。
2. 把药盒顶部完整放进画面。
3. 识别成功后，彩色图片会贴到药盒顶部。
4. 移动、远近、左右旋转药盒，图片会跟随目标做透视变化。

## 这次修复了什么闪烁问题

1. **坐标空间不匹配**：单应性矩阵是在 `target.jpg` 自己的像素坐标系里算出来的（1152×340），但代码直接把它套用到尺寸完全不同的 `ar-content.jpg`（1200×900）上，导致贴图内容被错误裁切，而且这个错位还会随姿态变化而抖动。现在会在加载时先把 `ar-content.jpg` 缩放进 `target.jpg` 的坐标系里，两者对齐后再做透视变换。
2. **每帧独立计算、没有平滑**：原来每一帧都重新检测特征点、独立解一次单应性矩阵，帧与帧之间的光照、运动模糊都会让匹配点数量波动，画面因此一直在跳。现在改成对四个角点做指数平滑（`SMOOTH` 常数，越小越稳但越有延迟），姿态是"平滑过渡"而不是"每帧重新拍脑袋"。
3. **识别失败就整帧清空**：原来只要这一帧匹配点不够、找不到单应性，画面就直接消失，下一帧识别成功又突然出现，造成一闪一闪。现在加入 500ms 的"保持"窗口（`HOLD_MS`）：短暂丢失识别时继续显示上一次的姿态并逐渐淡出，而不是硬生生消失。
4. **清空画布的时机不对**：原来每个动画帧都会 `clearRect`，但检测只在隔帧执行，导致贴图每两帧就被清空一次、造成规律性闪烁。现在只在 `processFrame` 真正要重绘时才清空画布。

## 如果画面仍然不够稳定，可以再试

- **重新裁剪 `target.jpg`**：目前这张图里还带着背景（桌面、木纹等），ORB 会在这些背景上也提取特征点，但背景不在药盒平面上，会破坏"整张图是一个平面"的假设，让内点数量不稳定。裁得只剩药盒顶部的印刷图案，几乎不留背景，追踪会稳很多。
- 调整 `index.html` 里的 `SMOOTH`（平滑系数）和 `HOLD_MS`（保持时长）常数，按实际体验微调"跟手程度"和"抗抖动程度"之间的平衡。
- 如果这套手写的 ORB 方案在不同光照/距离下还是不够鲁棒，可以按下面的下一版计划换成 MindAR 的 `.mind` 目标文件，它内置了姿态滤波，工程上会更稳定。

## 这是第一版原型

它现在追踪的是"药盒顶部的平面"，所以它更像 AR 贴图，而不是完整的 3D 物体跟踪。

下一版可以升级成：
- 估计药盒的 3D 姿态；
- 图片悬浮在药盒上方，而不是贴在表面；
- 药盒左右旋转时显示不同角度；
- 添加粒子、发光、动画；
- 换成真正的 3D 模型；
- 如果自然特征追踪不稳定，再改用 MindAR 的 `.mind` 目标文件。
